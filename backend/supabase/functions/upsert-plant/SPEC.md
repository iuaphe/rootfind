# upsert-plant

Insert or merge one plant or a batch of plants, including county links and common
names. This contract describes the handler and the upsert RPCs after migration
`202610240008_mobot_enrichment.sql` (inches and water arrays).

## Request and authorization

`POST /functions/v1/upsert-plant`

Send a JSON object for a single plant or an array of those objects for a batch.
Use `Content-Type: application/json`; the handler parses JSON without enforcing
the media type. Query parameters are not read or validated.

Provide a service-role credential in `Authorization: Bearer <credential>` or
`apikey: <credential>`. A nonempty Authorization value takes precedence over
`apikey`. The handler accepts either an exact match to its configured
`SUPABASE_SERVICE_ROLE_KEY` or a three-part token whose decoded payload has
`role: "service_role"`. The latter check only decodes the payload; it does not
verify the JWT signature, issuer, or expiry. Gateway JWT verification is disabled
in `supabase/config.toml`.

Database calls use the configured service-role key when present, otherwise the
provided credential. The handler defines no request-size limit, batch-count
limit, or rate limit of its own; platform limits may still apply.

## Payload

Each object has these properties:

| Property | Required | Accepted value |
| --- | --- | --- |
| `plant` | Yes | Object with the plant fields below |
| `counties` | No | Array of `{ "fips": <integer>, "name": <string> }` objects |
| `common_names` | No | Array of common-name strings |

Extra properties are ignored by the RPC. `counties` and `common_names` are
processed only when they are nonempty arrays; omission, null, an empty array,
or another JSON type skips their processing.

| `plant` field | Required | Accepted value / behavior |
| --- | --- | --- |
| `genus` | Yes | Nonblank string, trimmed of surrounding spaces, at most 100 characters after trimming |
| `species` | Yes | Nonblank string, trimmed of surrounding spaces, at most 100 characters after trimming |
| `life_cycle` | No | `perennial`, `biennial`, or `annual`; other values become null |
| `foliage` | No | `deciduous` or `evergreen`; other values become null |
| `measurement_units` | No | `feet` (default, including null) or `inches`; checked when a non-null measurement is supplied |
| `minheight`, `maxheight`, `minwidth`, `maxwidth` | No | Nonnegative numeric measurements; numeric strings are also accepted by the SQL cast. Converted inches must be at most 32767 before rounding. Minima round down and maxima round up. |
| `is_woody`, `is_tree`, `edible`, `thorns` | No | Boolean or null; values are parsed by PostgreSQL's boolean cast |
| `sun` | No | `full sun`, `part shade`, or `full shade`; other values become null |
| `water` | No | One string or an array of strings from `low`, `medium`, `high`; `med` aliases `medium`. Null/omitted means no supplied value; invalid levels or types raise an error. |
| `image_link` | No | String or null; no URL validation |
| `misc` | No | Array of strings; a non-array or empty array becomes null |

The RPC reads most scalar fields as JSON text and relies on SQL casts and
constraints rather than strict JSON-type validation. The types above are the
intended client representation. It does not check that minimum measurements are
less than or equal to maximum measurements.

`plant_id` is generated by the database and is not an accepted selector. Matching
uses the trimmed, case-sensitive `(genus, species)` pair. The RPC does not write
`min_zone`, `max_zone`, `bloom_months`, or taxonomy fields even if supplied.

County FIPS values must be integers from 0 to 99999; SQL integer-castable strings
also work. Missing/null or out-of-range FIPS values are skipped, while values
that cannot be cast to integers can fail the request. Nonblank county names are
trimmed and truncated to 100 characters, then inserted or used to update the
existing `county_info` record. A link with a missing/blank county name succeeds
only if that FIPS already exists; otherwise the foreign key fails. FIPS codes
are stored as integers without leading zeros.

Common names are trimmed and truncated to 100 characters. Blank/null names are
ignored; duplicates do not create duplicate names or links.

## Merge and transaction behavior

- A new `(genus, species)` pair creates a plant; an existing pair retains its ID.
- Non-null supplied scalar traits, image link, and `misc` replace existing
  values. Null/omitted values preserve existing values; this interface does not
  clear fields using null. Explicit `false` is a supplied value.
- Measurements expand the stored range: minima use the smaller non-null value,
  maxima the larger non-null value. Values are stored in integer inches, even
  when the request uses the default feet.
- Water levels are normalized, deduplicated, ordered `low`, `medium`, `high`, and
  merged with existing levels. An empty water array adds no levels and does not
  remove existing ones.
- County and common-name links are added without removing existing links.
  County name updates affect the shared county record.
- Each RPC call is transactional. A failure rolls back the single payload or
  the entire batch, including links and county-name changes. Batch items run
  in input order and may update the same plant repeatedly.

Example single request:

```http
POST /functions/v1/upsert-plant
Authorization: Bearer <service-role-key>
Content-Type: application/json

{
  "plant": {
    "genus": "Asclepias",
    "species": "tuberosa",
    "life_cycle": "perennial",
    "measurement_units": "inches",
    "minheight": 12,
    "maxheight": 36,
    "is_woody": false,
    "sun": "full sun",
    "water": ["low", "medium"]
  },
  "counties": [{"fips": 51059, "name": "Fairfax"}],
  "common_names": ["Butterfly weed"]
}
```

## Response

HTTP `200`, `Content-Type: application/json`. The handler forwards the RPC JSON
without wrapping it.

For a single object, the response is a bare integer plant ID:

```json
6
```

For a batch array, the response is:

```json
{"success":true,"count":2,"plant_ids":[6,9]}
```

`count` is the number of processed payloads, including updates, rather than the
number of newly inserted plants. `plant_ids` follows input order and may contain
duplicates. An empty batch returns `{"success":true,"count":0,"plant_ids":[]}`.

## Errors

| Status | Body / condition |
| --- | --- |
| `400` | `{"error":"Invalid JSON body: expected object or array"}` for a parsed null or primitive top-level value |
| `401` | `{"error":"Unauthorized: Service role key required for plant upsert"}` when the handler's credential check fails |
| `405` | `{"error":"Use POST"}` for unsupported methods |
| Upstream status below `500` | `{"error":"Database upsert failed","details":"<raw RPC response text>"}` for a non-success RPC response, including database validation/constraint failures |
| `502` | Same database-error body when the RPC status is `500` or greater |
| `500` | `{"error":"<exception message>"}` for exceptions, including malformed/missing JSON, missing URL, network failure, timeout, or invalid RPC JSON; `Internal error` for a non-Error exception |

Payload validation beyond the top-level object/array check happens in the RPC.
Malformed JSON currently returns `500`, rather than the `400` used for parsed
primitive/null bodies. RPC error text is exposed in `details`.

## HTTP behavior and dependencies

- `OPTIONS` returns `204` with no body before authorization or body parsing.
- CORS allows origin `*`, methods `POST, OPTIONS`, and request headers
  `authorization, apikey, content-type, x-client-info`.
- All responses use `Cache-Control: no-store`.
- Runtime settings are `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
- A single object calls `POST /rest/v1/rpc/upsert_plant`; an array calls
  `POST /rest/v1/rpc/upsert_plants_batch`. Both send `{"p_payload": <body>}`,
  use the chosen service-role credential in both `apikey` and bearer
  authorization headers, and apply a 15-second fetch timeout.
